Install

Python 3.9 or newer. From the project folder:

pip install .              # the library and the ghostpatterns command
pip install -e ".[dev]"    # editable, with pytest

Dependencies: numpy, pandas, scipy, scikit-learn and matplotlib.

Quick start

ghostpatterns analyse mushrooms.csv --target Mushroom_quality --open

This checks for leakage, mines rules that predict Mushroom_quality, tests them against 100 shuffled copies, finds the load-bearing columns, writes everything to results/mushrooms/ and opens the HTML report. It takes about five minutes on the 8,124-row Mushroom data.

Use a target when you have one. Asking "what predicts this column?" tests far fewer hypotheses than "what goes with what?", and the results are much sharper.

Reading the report

  • Ghost rate: rules the same mining finds in shuffled data. Report it next to your findings.
  • REAL (family-wise): beats the best rule of noise in at least 95% of runs. A headline result.
  • likely real (FDR): passes false-discovery-rate control. Report with a caveat.
  • GHOST: what noise produces anyway.
  • If noise produced no rules at all, per-rule p and q values are uninformative; read fwer_p. The log says so.

Python library

import pandas as pd
from ghostpatterns.analyse import Options, analyse, save

df = pd.read_csv("mushrooms.csv")
result = analyse(df, Options(target="Mushroom_quality", n_null=100))

print(result.headline())
print(result.rules.survivors.head())
save(result, "results/mushrooms")      # CSVs, figures, report.md, report.html

Shopping baskets, transactions, 0/1 matrixSwapRandomization

Numeric data, clusters or outliersGaussianMatched

Questions

Every rule came out REAL. Is something wrong?

Not necessarily. On strongly structured data like Mushroom, noise produces almost no rules at the default thresholds, so everything mined clears the bar. Check the leakage section, and lower --min-support or --min-lift to see the ghost distribution.

Nothing survived.

That is a result. Report it with the ghost rate. If you expected an effect, check that --n-null is at least 19 and that the sample is large enough; the benchmark's minimum detectable effect is a planted rise of about 0.30 in probability.

It is slow.

Each null run repeats the full mining. Use --no-attribution, a target column, fewer null runs while exploring, and 100 or more for final numbers.
